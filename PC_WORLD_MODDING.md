# PC: внешняя карта, модели и анимации

## Настройка карты

В `reVC.ini` (рядом с другими настройками игры) добавьте:

```ini
[World]
LoadViceCityMap=0
```

`1` или отсутствие ключа сохраняет обычную карту Vice City. `0` пропускает **только** штатные `IDE`/`IPL` из `data/maps` в `data/gta_vc.dat` и штатную воду `data/water.dat`/`data/waterpro.dat`. Системные ресурсы, другие записи DAT и ресурсы `custom/` продолжают загружаться. После изменения перезапустите игру. Если пользовательская карта требует собственной воды, её нужно реализовать отдельно: настройка не превращает VC-воду в воду произвольной карты.

Мир теперь хранит сектора за пределами исходной сетки −4000…4000 по X/Y в разреженной структуре. Внешние объекты проходят загрузку, рендер, коллизии и удаление RW-представления при удалении от камеры. Пустые внешние сектора не выделяются при чтении. Некоторые штатные системы — навигация, радар, миссии и таблицы воды — всё ещё привязаны к содержимому VC; бесконечный игровой мир этим изменением не создаётся.

## Распакованный `common/` (карта BR)

Разместите **уже распакованную** папку `common` в корне игры: `common/data/config.dat`, `common/data/maps/...`, `common/anim/ped.ani`. Копировать `common.dec.txt` как текст или добавлять `.bpc` не нужно. Парсер читает из `config.dat` **только активные** директивы `IDE` и `IPL`: в проверенном наборе это 75 IDE и 52 IPL. Закомментированные/event IPL не загружаются. Если нужно выбрать иной вариант сцены, укажите его полный путь относительно `common/`, по одной строке в `custom/active_ipl.txt` (например, `data/maps/Level_Events/BRmap_Event_DR.ipl` из исследованного набора). При наличии этого файла загружаются **только** перечисленные пользовательские IPL: добавляя событие, перечислите в том же файле и необходимые базовые IPL. Пустой список отключает все пользовательские размещения. Пути и регистр нормализуются, выход за пределы папки запрещён.

Файлы `common/`, перечисленные манифестом, применяются **после** IDE/IPL из `custom/`; при одинаковом пути версия из `common/` имеет приоритет. Повторные определения моделей сопоставляются по имени с уже зарегистрированными VC-моделями: совместимый тип использует прежний ID, несовместимый тип пропускается с диагностикой. Поддержаны `objs`, `tobj`, `anim` (как объекты), `peds`, `cars` и `weap`. Для новых записей требуется доступная модель `.dff`/`.mod` из `custom/`, IMG v1 + `.dir` из `img/` либо штатного IMG; без геометрии новая запись и зависящее от неё размещение пропускаются. TXD с именем модели из любого пользовательского IMG может лежать отдельно от DFF. Ресурсы **самих** `.bpc` не открываются, не декодируются и не монтируются. При индексировании IMG поиск моделей по имени использует временный индекс метаданных; лимиты кэшей и правила выгрузки объектов за камерой не меняются.

На полном проходе по **предоставленному** `common.dec.txt` настоящий сканер выбрал 75 IDE/52 IPL и прочитал 27 829 определений/99 673 размещения. Из выбранных IPL **40 имён (107 размещений) отсутствуют в выбранных IDE**; проверенные три невключённые IDE тоже их не содержат. Если уже зарегистрирована подходящая штатная VC-модель-здание с тем же именем и доступным DFF, она может использоваться по имени. Иначе нужны дополнительные совместимые определения IDE **и** геометрия DFF: подстановка модели по чужому SA ID или декодирование `.bpc` не выполняются. Во время запуска `debug.log` показывает суммарное число пропусков и до 16 наиболее частых отсутствующих имён; статистика разбора текста сама по себе не равна числу размещённых в игре объектов.

Транспорт регистрируется только для реализованных VC-классов `car`, `bike`, `boat`, `heli`, `plane`; неподдержанные `trailer`, `train`, `mtruck`, `quad`, `bmx`, `trike` и несовместимые совпадения имён пропускаются. Используется только существующий подходящий VC handling (или безопасный штатный вариант того же класса); BR/SA `handling.cfg`, `physics.json`, колёсные ID, правила случайного трафика и физика **не переносятся**. Ped-статистика/тип/группа анимации проверяются и отображаются в VC-диапазоны; SA-скелет использует **только** банк `custom`/`common/anim/ped.ani`, VC-скелет — штатный VC-банк. IDE оружия добавляет визуальные модели, но **не** новые типы оружия или стрельбу: поведение остаётся в VC `weapon.dat`. Из `common/data/carcols.dat` применяется только корректная палитра RGB (не SA-таблица моделей/handling). `audio/`/`AUDO`, `data/features/`, маршруты и прочие непереносимые конфиги игнорируются.

**Графика:** из `common/data/timecyc.json` берутся только ambient/directional свет и коэффициенты штатных теней для первых четырёх погод, интерполированные по часам. Если доступны графические пайплайны и render target, для `common/` включаются существующие NEO-отражения машин; световые карты — только на геометрии со вторым UV и DUAL-текстурой. При отказе RT сохраняется MatFX. Тени остаются штатными VC blob/static с выбранной силой: карты глубины и PCF из `GRAPHICS_ARCHITECTURE.md` **не реализованы**. Небо, вода, снег, gloss/rim, fog, PostFX и остальные эффекты отчёта не импортируются. Отсутствующие DFF/TXD/UV2 нельзя получить из одного текстового `common/`; требуется набор игровых моделей/текстур отдельно.

Смотрите `debug.log`: строки `common/:`, `BR IDE:`, `BR IPL:` показывают выбранные файлы, пропуски, ёмкость и числа размещений. С `LoadViceCityMap=0` начните **новую игру**, не загружайте старый VC-сейв без резервной копии. Автономные тесты проверяют парсер и приоритет, но игровой запуск с этим архивом не подтверждён.

## Пулы и сохранения

Пулы размещений, объектов, ped, транспорта, секторных ссылок и часть вспомогательных пулов растут блоками, не меняя адреса ранее созданных объектов. Хранилища model info, включая модели оружия и ped, также растут без перемещения записей. Это **не** означает снятие всех технических ограничений: ID моделей/эффектов и таблицы стриминга ограничены представлением ID, handle пула — знаковым 32-битным числом со старшими битами номера слота. Типы оружия (`WEAPONTYPE_TOTALWEAPONS=37`), слоты оружия ped и таблица игровых анимаций остаются фиксированными. Лимиты кэшей `.mod`/`.btx`/TXD не менялись; старое поведение выгрузки моделей за камерой сохраняется.

PC-сохранение сохраняет старый формат. Растущие ped/vehicle/object-блоки теперь сначала измеряются и записываются через отдельный буфер, без переполнения прежнего `work_buff` на 55 КБ. Если суммарный объём превышает **201729 байт** штатного формата, запись отклоняется с сообщением в `debug.log`. На PC запись идёт во временный `.pending`, который заменяет сохранение только после успешной записи и закрытия файла; прежний слот при отказе остаётся нетронутым. Сохраните резервные копии игровых сейвов перед тестированием модов. Полный цикл сохранения/загрузки с игровыми ресурсами пока не проверен.

## Переключение скина

В игре, пешком, нажмите `-`/`+` на основной клавиатуре (для `+` — `Shift` + `=`) либо `Num -`/`Num +`. Перебираются зарегистрированные ped-модели, в том числе пользовательские ID; неподгружаемый кандидат пропускается. Во время катсцен, повтора, в автомобиле или в меню переключение отключено. Текущий объект игрока заменяется с пересозданием его визуальной модели и привязки оружия. Совместимость произвольного DFF с игровым скелетом/состоянием после переключения должна проверяться в игре.

## Диагностика запуска и SA-анимаций

**Новый `debug.log` с `7b2eabd`, VC-карта выключена:** защита эскалаторов сработала (`Skipping native VC escalators`, затем `moving things ready`), но после запуска `main.scm` произошёл другой сбой — чтение `0x1D`, RVA EXE `0x7D9CC`. Совпадающая **Release D3D9 EXE/PDB из CI этого merge** указала `CPickup::GiveUsAPickUpObject`, `src/control/Pickups.cpp:188`: разыменование `CModelInfo::GetModelInfo(m_eModelIndex)` при отсутствующей модели пикапа. В логе отключённой карты есть пропущенные штатные VC IDE и отсутствующие VC-имена (включая `BRIBE` и `PICKUPSAVE`); какой именно ID вызвал это обращение, старый лог не записал. Повторное открытие `main.scm` штатно для запуска миссии и само по себе не является причиной сбоя. Теперь создание пикапа с отсутствующей/неподходящей моделью возвращает `-1` **до** занятия слота или вызова `CObject`, записывая ID/тип/позицию; скрипт не ставит blip для несуществующего пикапа. Пикапы из сохранений с отсутствующей моделью снимаются при обновлении. При выключенной VC-карте штатный скрипт всё ещё может требовать отключённые IDE/IPL: такой пикап будет пропущен, а не восстановлен. Реальный запуск на наборе пользователя ещё требуется для подтверждения отсутствия последующих ошибок.

**Повторный `debug.log` с EXE `16a4efe`, `LoadViceCityMap=0`:** защита пикапов сработала: скрипт пропустил 13 запросов модели `0` (это ped-модель, не модель пикапа) и штатные property pickup с индексом `-1`. Сбой теперь происходит при загрузке существующего `userfiles\\GTAVCsf1.b`, после записи `Loading GameLogic`. Совпадающая **Release D3D9 EXE/PDB** из PR-run `39619341403` указала на `IsGlass` (`ModelIndices.h:485`): чтение `m_type` по адресу `0x1D` через отсутствующий model info (RVA `0x15053F`). Последняя запись **не** доказывает сбой именно в `CGameLogic::Load`: эта функция только читает координаты, а следующие блоки восстановления машин/объектов не выводили меток. Старый лог не содержит конкретного ID проблемной модели и содержимого сейва.

Теперь `IsGlass` безопасно отрабатывает отсутствующий/неподходящий ID. Перед восстановлением PC-пулов машин и объектов проверяются **все записи блока**: длины, типы, модели и их соответствие текущим IDE. При несовместимости загрузка отклоняется с моделью/типом/номером записи в `debug.log` **до создания сущностей этого пула**; исходный файл сохранения не перезаписывается. Пропускать одну машину или объект внутри сейва нельзя — хэндлы скриптов и пикапов ссылаются на слоты пула. Сохранение с включённой VC-картой может быть несовместимо с `LoadViceCityMap=0`: для проверки нового мира начните **новую игру**, предварительно сохранив резервную копию старого сейва. Один лишь совпадающий ID модели не гарантирует одинаковое содержимое IDE; полная миграция старых сейвов между картами не реализована. После изменения кода запуск с пользовательским сейвом и без него пока не подтверждён.

**Предыдущий `debug.log` с `4fae341`:** после загрузки IFP падение на `0x20` происходило до запуска скрипта, при инициализации VC-эскалаторов без `Esc_step`. Штатные VC-эскалаторы теперь пропускаются без VC-карты или подходящей модели/коллизии. Точный адрес старого сбоя `RVA 0x22D933` не символизировался; новый лог подтверждает, что стадия эскалаторов успешно пройдена.

**Исторические логи от 20.10.2026** сняты с `9a56945` — это merge прежнего PC-коммита `b85218c` в базовую ветку, а не отдельная правка анимаций:

- `debug1.log`, **VC-карта включена**: игра дошла до геймплея. Сканирование `custom/` нашло **один** `.ifp/.ani` — `custom/ped.ifp` → `sa_ped` (1 433 248 байт). 161 SA-слот остался без иерархии. Четыре предупреждения `Weapon animation unavailable` относятся к SA-скелетам: модель 0/оружие 20/группа `buddy`/клип `buddy_fire`; 0/25/`uzi`/`UZI_fire`; 56/11/`chainsaw`/`csaw_part` (в SA-банке `CSAW_PART`); 34/18/`python`/`python_fire`. `Bike roll animation missing` тоже остаётся. После `Quit requested` лог обрывается во время выключения, поэтому полное штатное завершение этим файлом **не подтверждено**.
- `debug.log`, **VC-карта выключена**: до IFP или геймплея не дошло. При чтении `MODELS\GTA3.DIR` сработал `CDirectory::AddItem: numEntries < maxEntries` (SIGABRT): при пропуске штатных VC IDE больше штатных DFF становятся «без IDE», а каталог script-loadable дополнительных моделей был ограничен 256 записями. Теперь он растёт при добавлении, сохраняет ранее зарегистрированные объекты и приоритет первого IMG. Это исправление проверено тестом на 1400 моделей и пройдено в более свежем логе; новое падение после инициализации часов — другой путь.

VC-скелеты получают **только штатные VC-анимации**; SA-скелеты — только словари `ANP2`/`ANP3` (`.ifp` или `.ani`) из `custom/` либо ZIP внутри неё. VC-клипы нельзя подставлять вместо отсутствующих SA-клипов. В прежнем запуске был только `ped.ifp`: он содержит базовые движения, **не** перечисленные выше оружейные банки. При повторении таких предупреждений нужны совместимые собственные `buddy.ifp`, `uzi.ifp`, `python.ifp`, `chainsaw.ifp` в `custom/` (либо одноимённые `.ani` / файлы в ZIP) **в дополнение** к `ped.ifp`. В новой установке пользователь уже добавил анимации; эти старые предупреждения не объясняют падение при выключении карты. Код также ищет `shotgun`, `tec`, `colt45`, `rifle`, `sniper`, `flame` и другие SA-банки. Проверьте после запуска записи `animation ANIM\<имя>.IFP: loaded in parallel bank sa_<имя>` и исчезновение конкретных предупреждений при стрельбе тем же оружием; теперь предупреждение указывает группу и имя нужного клипа. Если словарь загружен, но клип или подходящая SA-иерархия отсутствует, анимация останется недоступна.

Без самих совместимых ресурсов программная подстановка VC-анимации не восстановит стрельбу SA-педа. Ранее приложенный одноимённый лог от `c5e1b03` — **другой** запуск: там также не хватало SA-клипов, но он дошёл до `Shutdown complete`; вывод об отсутствии краша из него не относится к новому `debug.log`. Точечные защиты урона/смерти/боёв и выхода с байка не гарантируют корректную визуальную анимацию без собственных SA-файлов. Формат разобран в приложенном пользователем `IFP_FORMAT.md` (не поставляется в репозитории).

## Проверка

Автономные тесты: `cmake -S tests -B build/tests/pc -G Ninja && cmake --build build/tests/pc && ctest --test-dir build/tests/pc --output-on-failure`. Для реального PC-теста нужны установленная Vice City, зависимая от платформы сборка игры и подходящие пользовательские IDE/IPL/DFF/TXD/IFP; тесты не воспроизводят игровое поведение. Если есть проблема с анимацией, приложите свежий `debug.log` той же версии EXE, используемый `custom/` набор и шаги воспроизведения (без чужих защищённых ассетов в PR).
