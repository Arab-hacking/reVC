# Миграция ресурсов из прежнего `common/`

**Корневая папка `common/` не является источником пользовательских ресурсов.** Однако `custom/common.zip` читается **выборочно**: из него берутся IDE/IPL, три корневых IDE, конфиг выбора IPL, освещение, вода и палитра. Остальные файлы внутри ZIP остаются отключены.

| Прежний ресурс | Новое место / действие |
|---|---|
| `common/data/maps/**/*.ide`, `**/*.ipl` | Перенесите файлы в `custom/data/maps/` с той же структурой **или** сохраните архив как `custom/common.zip` с путями `data/maps/...` (старые `maps/...` тоже распознаются). Запись ZIP того же пути выигрывает; распакованный файл служит резервом, если архивную запись не удалось прочитать. Дубликат не загружается повторно. |
| `common/data/peds.ide`, `common/data/vehicles.ide`, `common/data/weapons.ide` | Читаются **только** из `custom/common.zip` как три одноимённых корневых IDE внутри архива. Регистр путей не важен. Для видимых моделей нужны подходящие DFF/TXD в `custom/img/` или совпадающие штатные VC-модели; неподдержанные типы пропускаются. `weapons.ide` добавляет только модели, не новые типы/поведение оружия. Корневые loose `custom/data/*.ide` и прочие корневые IDE не читаются. |
| Активные `IDE`/`IPL` в `common/data/config.dat` | Корневой файл игнорируется. Если конфиг находится **внутри `custom/common.zip`** как `data/config.dat`, его директивы `IPL` задают набор IPL при отсутствии `custom/data/maps/active_ipl.txt`. IDE не фильтруются. Без применимого конфига читаются все IPL. Явный список (включая базовые пути) перекрывает конфиг. |
| Модели/текстуры из старых ZIP/IMG v2/BR-контейнеров | Подготовьте совместимые DFF/TXD, упакуйте в VC IMG v1 с внешним DIR и положите пару в `custom/img/`. Поиск одноимённого TXD идёт среди всех таких IMG. |
| `common/anim/ped.ani` и другие `.ani` | Подготовьте совместимые ANP2/ANP3 `.ifp` и положите их в `custom/anim/`. VC-скелеты всегда используют штатный VC-банк. |
| `.col`/`.cls` в ZIP или `br_collision.img` | Скопируйте пару `br_collision.img` + `br_collision.dir` (VC IMG v1) в `custom/img/`. Отдельные COL/CLS из ZIP тоже нужно упаковать в совместимую IMG/DIR-пару. Папка `custom/collision/` не читается; блоки сопоставляются по внутреннему имени модели. |
| `common/data/timecyc.json` | Корневой файл не читается. Допустимы `data/timecyc.json` внутри `custom/common.zip` (приоритет) и loose `custom/data/timecyc.json` (резерв); ambient/directional свет и сила штатных теней; в GL3 при `GL3Atmosphere=1` также цвета неба/солнца/облаков и безопасно масштабированное начало тумана (не FarClip). |
| `common/data/water.dat` | Только `data/water.dat` внутри `custom/common.zip`: проверенные прямоугольники SA `processed`, включая наклонные, заменяют штатную VC-воду; при неверном ZIP — штатная вода (или отсутствие воды при выключенной VC-карте). SA-течения/параметры волн не импортируются. |
| `common/data/carcols.dat` | Только `data/carcols.dat` внутри `custom/common.zip`: проверенные RGB-тройки SA `col` заменяют VC-палитру по индексу; штатные комбинации цветов моделей не меняются. |
| `*.bpc`, `audio/AUDO`, `data/features/`, физика/handling | Не импортируются. |
| `.btx` отражений и световых карт в `zip/*.zip` | Отключены; нет резервного графического ZIP-пути. |

Штатные ресурсы самой Vice City продолжают читаться игровым загрузчиком. Модели без доступной геометрии и непригодные IDE/IPL/коллизии пропускаются и протоколируются; чтение `custom/common.zip` само по себе **не** исправляет ошибки видимой DFF-геометрии и не делает `.mod`/`.btx` игровыми DFF/TXD. Подробности: [CUSTOM_MODELS.md](CUSTOM_MODELS.md) и [PC_WORLD_MODDING.md](PC_WORLD_MODDING.md).
