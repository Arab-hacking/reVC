# Пользовательские ресурсы reVC: расположение файлов

Игра читает **только указанные папки и один архив** внутри `<каталог игры>/custom/` (или внутри `REVC_CUSTOM_DIR`, если переменная задана):

```text
custom/
  common.zip                # необязательно: data/maps/**/*.ide, **/*.ipl,
                            # data/peds.ide, data/vehicles.ide, data/weapons.ide,
                            # data/config.dat, data/timecyc.json,
                            # data/water.dat, data/carcols.dat
  anim/
    ped.ifp                 # SA-анимации; при необходимости другие банки *.ifp
  img/
    map.img                 # DFF/TXD и, при наличии, COL/CLS
    map.dir                 # одноимённый внешний каталог VC IMG v1
    br_collision.img        # пример IMG только с .col/.cls
    br_collision.dir        # внешний DIR с именами COL/CLS-записей
    vehicles/               # необязательные подпапки, до 8 уровней
      cars.img
      cars.dir
  data/maps/
    ide/objects.ide         # определения объектов
    level/objects.ipl       # размещения
    active_ipl.txt          # необязательный список выбранных IPL
  data/timecyc.json         # свет/тени; в GL3 также небо/облака/начало тумана
```

Папка `custom/img/` монтируется **до** индексации потоковых файлов; DFF/TXD используют штатный IMG-стример, а COL/CLS из любого пользовательского IMG читаются отдельным проверяемым путём и переводятся в VC COLL. Архивы только с коллизиями, например `br_collision.img` + `br_collision.dir`, тоже монтируются. IFP внутри IMG не используются. Игра по-прежнему читает свои штатные VC IMG/IFP/IDE: изменение относится **только** к дополнительным пользовательским ресурсам.

**Единственное ZIP-исключение — `custom/common.zip`:** из него читаются IDE/IPL в `data/maps/` (старый псевдоним `maps/` также понимается), **ровно три корневых IDE: `data/peds.ide`, `data/vehicles.ide`, `data/weapons.ide`**, `data/config.dat` для выбора IPL, `data/timecyc.json` для света и, в GL3, атмосферы, а также `data/water.dat` и `data/carcols.dat`. Другие корневые IDE, например `data/misc.ide`, не импортируются. При совпадении относительного пути карты или `timecyc.json` приоритет у записи `custom/common.zip`; одноимённая карта не загружается дважды. Имена архива без учёта регистра, относительные пути проверяются, одна запись ограничена 64 МиБ (для воды — 1 МиБ, палитры — 64 КиБ). Если запись ZIP не читается, резервный распакованный файл используется **только для карт и `timecyc.json`**; корневые IDE, вода и таблица цветов из `custom/data/` не сканируются.

**Не загружаются:** все прочие пользовательские ZIP (`custom/old.zip`, `zip/*.zip`, вложенные ZIP), а из `custom/common.zip` — DFF/TXD/COL/CLS/IFP/MOD/BTX и другие файлы; также корневые `img/*.img`, `common/`, папка `custom/collision/` и отдельные `.mod`, `.btx`, `.dff`, `.txd`, `.col`, `.cls`, `.ifp`, `.ide`, `.ipl` в старых местах. Распаковать ZIP и оставить файлы в `custom/` недостаточно: разместите **совместимые** файлы в папках и форматах выше. `.ani` не сканируются: для совместимых ANP2/ANP3-анимаций подготовьте `.ifp` отдельно. `.bpc`, аудио/AUDO, `data/features/` и физика автомобилей не импортируются. Конфиг из **корневого** `common/data/config.dat` не используется.

## IMG: модели, текстуры и коллизии

* Для каждого `*.img` нужен одноимённый `*.dir` рядом с ним. Формат — **VC/GTA3 IMG v1**: сырые 2048-байтные секторы и внешний каталог из 32-байтных записей. SA IMG v2 (`VER2`) пропускается. Пути IMG должны умещаться в 63 байта из-за формата `CdStream` (в том числе при абсолютном `REVC_CUSTOM_DIR`); об отсутствии DIR, неверном формате или лимите слотов пишется в `debug.log`.
* В DIR имена `*.dff` соответствуют именам моделей из IDE; `*.txd` содержат текстуры материалов. Записи `*.col`/`*.cls` могут находиться в том же IMG или в отдельном IMG без DFF/TXD. Для каждого DFF игра ищет одноимённый TXD **среди всех смонтированных пользовательских IMG**, даже если он лежит в другом IMG и IDE называет другой словарь. Если пары нет, сохраняется обычное имя TXD из IDE. Штатный движок загружает TXD перед DFF и выгружает модель, когда она вне обзора. Никакой ZIP-замены моделей/текстур при этом нет.
* При совпадении имени используется приоритет игрового IMG-стримера; обычно последний смонтированный IMG перекрывает более ранний. Для скриптовой special-модели DFF разыскивается среди смонтированных IMG и штатного IMG игры **до** смены имени слота. Тип загрузчика определяется записью IDE (статический объект, ped, транспорт), а не расширением файла.
* Если исходные ресурсы представлены только как `.mod`/`.btx` или как SA IMG v2, подготовьте их совместимый DFF/TXD и упаковку IMG v1 **вне игры**. Существующие утилиты исследования форматов не означают, что игра снова читает ZIP. Не добавляйте проприетарные игровые ассеты в PR.

## IDE/IPL: карта

Разместите IDE/IPL карты в `custom/data/maps/` (с подпапками) или в `custom/common.zip` по путям `data/maps/**/*.ide`/`**/*.ipl`. Дополнительно ZIP читает `data/peds.ide` (секция `peds`), `data/vehicles.ide` (секция `cars`) и `data/weapons.ide` (секция `weap`); для этих визуальных моделей нужны совместимые DFF/TXD в `custom/img/` или штатные VC-модели, если имя и тип совпадают. Одних записей IDE для видимых педов, машин и оружия недостаточно; `weapons.ide` не добавляет новые типы стрельбы или поведение VC `weapon.dat`. Старые архивные пути `maps/...` приводятся к `data/maps/...`; если есть оба архивных пути, выигрывает `data/maps/...`, а над распакованным файлом того же пути — запись ZIP. Имена регистронезависимы; в callback передаётся относительный путь вида `data/maps/ide/objects.ide`. Все IDE читаются независимо от выбора IPL; записи сопоставляются по имени с уже зарегистрированными VC-моделями, чтобы исходные BR ID не использовались как индексы VC. Для новой модели нужен доступный DFF в смонтированном IMG (либо подходящая штатная модель). Некорректные записи, несовместимые типы и размещения без модели пропускаются с диагностикой.

Без списка выбора читаются IPL из `custom/data/maps/` и `custom/common.zip`, указанные директивами `IPL` в архивном `data/config.dat`. Если конфиг отсутствует, не читается или ни один путь не совпал с имеющимися IPL, читаются **все** доступные IPL. Все IDE читаются в любом случае (архивный список `IDE` их не отфильтровывает). Для явного выбора альтернативных сцен создайте `custom/data/maps/active_ipl.txt` — он имеет приоритет над архивным конфигом. Укажите **каждый нужный IPL**, включая базовые, по одному полному пути относительно `custom/` на строку:

```text
# только эта сцена; пути и регистр нормализуются
DATA\MAPS\LEVEL\objects.ipl
```

Пустой список отключает все пользовательские IPL, но не IDE. Строки с `#` и `//` допускаются; пути вне `data/maps/`, неизвестные IPL и переходы `..` отклоняются/протоколируются. Старый `custom/active_ipl.txt` и корневой `common/data/config.dat` **не** используются. Если `custom/data/maps/` отсутствует, архивный `data/config.dat` всё равно применяется. Чтобы отключить только штатную карту Vice City, задайте в `reVC.ini` `[World] LoadViceCityMap=0` и начните новую игру: старый VC-сейв может ссылаться на отключённые IDE. Подробности: [PC_WORLD_MODDING.md](PC_WORLD_MODDING.md).

## Коллизии и анимации

Коллизии берутся **только из записей `.col`/`.cls` в парных IMG/DIR под `custom/img/`**; папка `custom/collision/` и отдельные `.col`/`.cls` больше не читаются. Подойдёт и `br_collision.img` без DFF/TXD. Запись DIR задаёт ограниченный диапазон секторов; некорректная запись COL/CLS пропускается, не скрывая остальные записи архива. Сопоставление каждого блока идёт по **внутреннему имени модели**, а не по имени IMG или записи. Совместимые COLL проходят проверку границ; COL2/COL3 и старый CLS конвертируются в VC COLL в памяти. Записи `.cls` читает один разборщик по раскладке из анализа v45 (§10.3): имя в 24 байтах, массивы адресуются от заголовка структуры, блок AABB пропускается как ускоряющая структура, а запись без геометрии отклоняется с причиной в `debug.log` и не устанавливает пустую модель. Для модели с COL и CLS приоритет у COL; более поздний смонтированный IMG выигрывает среди записей одного вида. Нативный стример не получает сырой SA COL. Повреждённые блоки не передаются игровому загрузчику. Стандартные VC-коллизии остаются доступны.

`custom/anim/*.ifp` загружаются в отдельные SA-банки только для **SA-скелетов**; VC-скелеты используют только штатные VC-анимации. SA-клип не заменяется VC-клипом при отсутствии собственного банка. Помимо `ped.ifp` для конкретного SA-оружия могут понадобиться `buddy.ifp`, `uzi.ifp`, `python.ifp`, `chainsaw.ifp` и другие совместимые словари. Поддерживаются ANP2/ANP3 с проверкой формата; пользовательский ANPK не подменяет штатный VC-словарь. Изолированная папка `custom/anim/` не означает чтения `.ifp` из пользовательского ZIP.

## Вода и цвета из `custom/common.zip`

`data/water.dat` читается как **SA `processed`-формат**, а не как VC `WATER.DAT`: каждая запись задаёт четыре угла прямоугольника и высоты воды в них. Поддержаны проверенные осево ориентированные плоские и наклонные четырёхугольники (в присланном файле — 366); поверхность рисуется и участвует в запросах высоты/плавучести также за границами штатной VC-сетки. Используются штатные VC-текстуры/цвета воды; SA-потоки, параметры волн и другие типы полигонов пока не переносим. Неподдержанные/неверные строки пропускаются и подсчитываются в `debug.log`. При наличии хотя бы одного пригодного четырёхугольника архивная вода заменяет **и `WATER.DAT`, и `WATERPRO.DAT` Vice City**; при отсутствии или непригодности записи остаётся штатная вода, если `LoadViceCityMap=1`, иначе воды нет. Корневые `common/data/water.dat` и распакованный `custom/data/water.dat` не читаются. Это не создаёт коллизию земли для генераторов автомобилей.

`data/carcols.dat` из ZIP задаёт только проверенные RGB-цвета из секции SA `col` (не более 256). После загрузки штатной таблицы Vice City палитра заменяется по индексу; отсутствующие индексы и штатные комбинации цветов машин остаются прежними. Палитра влияет и на штатные VC-модели. В присланном файле — 255 цветов; **назначения `car`/`car4`, физика и трафик не импортируются**. При испорченном файле сохраняется штатная палитра. Распакованные `custom/data/carcols.dat` и корневой `common/data/carcols.dat` не используются.

## Дополнительное освещение и ограничения

`data/timecyc.json` читается сначала из `custom/common.zip`, затем как распакованный `custom/data/timecyc.json` (если запись ZIP отсутствует или не читается). Ambient/directional освещение и сила штатных теней первых четырёх погод работают на всех бэкендах. **Только GL3 при `[Rendering] GL3Atmosphere=1` (по умолчанию):** импортируются интерполированные цвета верха/низа неба, солнца и облаков; `FogStart` переносится как доля `FarClip` исходного таймцикла на **штатную** дальность VC, чтобы не обрезать внешнюю карту. Погода меняет мягкость солнечного блика и насыщенность воздушной дымки. При `GL3Atmosphere=0` остаются прежние небо/туман и освещение. Вода, дальность отсечения, снег, PostFX и другие пресеты из JSON не импортируются; вода из `data/water.dat` читается отдельно, как описано выше. Корневой `common/data/timecyc.json` и `zip/*.zip` не используются. Пользовательские `.btx` отражений/lightmap из **любого** ZIP, включая `custom/common.zip`, отключены; рендерер не включает Neo-отражения/подмену DUAL-текстур на основании этих архивов. Обычные встроенные игровые эффекты не отключаются. См. [PC_GRAPHICS_ZIP.md](PC_GRAPHICS_ZIP.md).

Лимиты ранее существовавших CPU/GPU-кэшей не повышались ради новой раскладки. Ограничения потоковых слотов IMG и максимальной длины пути остаются; порог одной IMG-записи коллизии, loose-файла анимации/карты или обычной записи `common.zip` — 64 МиБ (вода/палитра ограничены строже, см. выше). Архив поддерживает stored/deflate и ZIP64; остальные методы отклоняются. Ресурсы индексируются при запуске, поэтому после замены файлов перезапустите игру. Лог `debug.log` содержит скан `common.zip`, выбор IPL, монтирование IMG, чтение IDE/IPL/коллизий/IFP и причины пропусков. Успешная сборка/тесты **не** подтверждают отсутствие runtime-краша или видимой DFF-геометрии на вашем конкретном наборе; для проверки нужны свежий лог той же версии EXE и шаги воспроизведения.

Автономная проверка (Linux): `cmake -S tests -B build/tests -G Ninja && cmake --build build/tests && ctest --test-dir build/tests --output-on-failure`. `custom_archive_integration_tests` использует настоящий сканер и монтирование IMG (включая IMG только с COL/CLS), проверяет чтение `custom/common.zip` (включая три корневых IDE, воду и палитру), его приоритет и возврат к распакованным картам/освещению при ошибке чтения ZIP, а также **отрицательные** тесты loose `custom/collision/`, прочих ZIP, корневых `img/` и `common/`.
