# Пользовательские ресурсы reVC: расположение файлов

Игра читает **только явно указанные папки** внутри `<каталог игры>/custom/` (или внутри `REVC_CUSTOM_DIR`, если переменная задана):

```text
custom/
  anim/
    ped.ifp                 # SA-анимации; при необходимости другие банки *.ifp
  img/
    map.img                 # DFF/TXD и, при наличии, COL/CLS
    map.dir                 # одноимённый внешний каталог VC IMG v1
    br_collision.img        # пример IMG только с .col/.cls
    br_collision.dir        # внешний DIR с именами COL/CLS-записей
    vehicles/               # необязательные подпапки, до 8 уровней
      cars.img
      cars.dir
  data/maps/
    ide/objects.ide         # определения объектов
    level/objects.ipl       # размещения
    active_ipl.txt          # необязательный список выбранных IPL
  data/timecyc.json         # необязательный свет/сила штатных теней
```

Папка `custom/img/` монтируется **до** индексации потоковых файлов; DFF/TXD используют штатный IMG-стример, а COL/CLS из любого пользовательского IMG читаются отдельным проверяемым путём и переводятся в VC COLL. Архивы только с коллизиями, например `br_collision.img` + `br_collision.dir`, тоже монтируются. IFP внутри IMG не используются. Игра по-прежнему читает свои штатные VC IMG/IFP/IDE: изменение относится **только** к дополнительным пользовательским ресурсам.

**Не загружаются:** любые пользовательские ZIP (`custom/*.zip`, `zip/*.zip`, вложенные ZIP, включая `.btx` отражений и lightmap), корневые `img/*.img`, `common/`, папка `custom/collision/`, а также отдельные `.mod`, `.btx`, `.dff`, `.txd`, `.col`, `.cls`, `.ifp`, `.ide`, `.ipl` в старых местах. Распаковать ZIP и оставить файлы в `custom/` недостаточно: разместите **совместимые** файлы в папках и форматах выше. `.ani` не сканируются: если это совместимые ANP2/ANP3-анимации, подготовьте соответствующие `.ifp` отдельно. `.bpc`, аудио/AUDO, `data/features/` и физика автомобилей не импортируются. `common/data/config.dat` больше не определяет активные карты.

## IMG: модели, текстуры и коллизии

* Для каждого `*.img` нужен одноимённый `*.dir` рядом с ним. Формат — **VC/GTA3 IMG v1**: сырые 2048-байтные секторы и внешний каталог из 32-байтных записей. SA IMG v2 (`VER2`) пропускается. Пути IMG должны умещаться в 63 байта из-за формата `CdStream` (в том числе при абсолютном `REVC_CUSTOM_DIR`); об отсутствии DIR, неверном формате или лимите слотов пишется в `debug.log`.
* В DIR имена `*.dff` соответствуют именам моделей из IDE; `*.txd` содержат текстуры материалов. Записи `*.col`/`*.cls` могут находиться в том же IMG или в отдельном IMG без DFF/TXD. Для каждого DFF игра ищет одноимённый TXD **среди всех смонтированных пользовательских IMG**, даже если он лежит в другом IMG и IDE называет другой словарь. Если пары нет, сохраняется обычное имя TXD из IDE. Штатный движок загружает TXD перед DFF и выгружает модель, когда она вне обзора. Никакой ZIP-замены моделей/текстур при этом нет.
* При совпадении имени используется приоритет игрового IMG-стримера; обычно последний смонтированный IMG перекрывает более ранний. Для скриптовой special-модели DFF разыскивается среди смонтированных IMG и штатного IMG игры **до** смены имени слота. Тип загрузчика определяется записью IDE (статический объект, ped, транспорт), а не расширением файла.
* Если исходные ресурсы представлены только как `.mod`/`.btx` или как SA IMG v2, подготовьте их совместимый DFF/TXD и упаковку IMG v1 **вне игры**. Существующие утилиты исследования форматов не означают, что игра снова читает ZIP. Не добавляйте проприетарные игровые ассеты в PR.

## IDE/IPL: карта

Разместите `*.ide` и `*.ipl` в `custom/data/maps/` или её подпапках. Имена регистронезависимы; в callback передаётся относительный путь вида `data/maps/ide/objects.ide`. Все IDE читаются независимо от выбора IPL; записи сопоставляются по имени с уже зарегистрированными VC-моделями, чтобы исходные BR ID не использовались как индексы VC. Для новой модели нужен доступный DFF в смонтированном IMG (либо подходящая штатная модель). Некорректные записи, несовместимые типы и размещения без модели пропускаются с диагностикой.

По умолчанию читаются **все** IPL в `custom/data/maps/`. Если набор содержит взаимоисключающие варианты (события, гонки, растительность), создайте `custom/data/maps/active_ipl.txt`. Укажите **каждый нужный IPL**, включая базовые, по одному полному пути относительно `custom/` на строку:

```text
# только эта сцена; пути и регистр нормализуются
DATA\MAPS\LEVEL\objects.ipl
```

Пустой список отключает все пользовательские IPL, но не IDE. Строки с `#` и `//` допускаются; пути вне `data/maps/`, неизвестные IPL и переходы `..` отклоняются/протоколируются. Старый `custom/active_ipl.txt` и `common/data/config.dat` **не** используются. Чтобы отключить только штатную карту Vice City, задайте в `reVC.ini` `[World] LoadViceCityMap=0` и начните новую игру: старый VC-сейв может ссылаться на отключённые IDE. Подробности: [PC_WORLD_MODDING.md](PC_WORLD_MODDING.md).

## Коллизии и анимации

Коллизии берутся **только из записей `.col`/`.cls` в парных IMG/DIR под `custom/img/`**; папка `custom/collision/` и отдельные `.col`/`.cls` больше не читаются. Подойдёт и `br_collision.img` без DFF/TXD. Запись DIR задаёт ограниченный диапазон секторов; некорректная запись COL/CLS пропускается, не скрывая остальные записи архива. Сопоставление каждого блока идёт по **внутреннему имени модели**, а не по имени IMG или записи. Совместимые COLL проходят проверку границ; COL2/COL3 и старый CLS конвертируются в VC COLL в памяти. BR CED2 из CLS проходит отдельный путь проверки. Для модели с COL и CLS приоритет у COL; более поздний смонтированный IMG выигрывает среди записей одного вида. Нативный стример не получает сырой SA COL. Повреждённые блоки не передаются игровому загрузчику. Стандартные VC-коллизии остаются доступны.

`custom/anim/*.ifp` загружаются в отдельные SA-банки только для **SA-скелетов**; VC-скелеты используют только штатные VC-анимации. SA-клип не заменяется VC-клипом при отсутствии собственного банка. Помимо `ped.ifp` для конкретного SA-оружия могут понадобиться `buddy.ifp`, `uzi.ifp`, `python.ifp`, `chainsaw.ifp` и другие совместимые словари. Поддерживаются ANP2/ANP3 с проверкой формата; пользовательский ANPK не подменяет штатный VC-словарь. Изолированная папка `custom/anim/` не означает чтения `.ifp` из пользовательского ZIP.

## Дополнительное освещение и ограничения

Если используется `custom/data/timecyc.json`, применяются **только** ambient/directional освещение и сила штатных теней для поддерживаемых погод. Небо, вода, туман, снег, PostFX и серверные пресеты не импортируются. `common/data/timecyc.json` и `zip/*.zip` не используются. Пользовательские `.btx` отражений/lightmap из ZIP **отключены**; рендерер не включает Neo-отражения/подмену DUAL-текстур на основании этих архивов. Обычные встроенные игровые эффекты не отключаются. См. [PC_GRAPHICS_ZIP.md](PC_GRAPHICS_ZIP.md).

Лимиты ранее существовавших CPU/GPU-кэшей не повышались ради новой раскладки. Ограничения потоковых слотов IMG и максимальной длины пути остаются; порог одного IMG-записи коллизии или loose-файла анимации/карты — 64 МиБ. Ресурсы индексируются при запуске, поэтому после замены файлов перезапустите игру. Лог `debug.log` содержит скан, монтирование IMG, чтение IDE/IPL/коллизий/IFP и причины пропусков. Успешная сборка/тесты **не** подтверждают отсутствие runtime-краша на вашем конкретном наборе; для такой проверки нужны свежий лог той же версии EXE и шаги воспроизведения.

Автономная проверка (Linux): `cmake -S tests -B build/tests -G Ninja && cmake --build build/tests && ctest --test-dir build/tests --output-on-failure`. `custom_archive_integration_tests` использует настоящий сканер и монтирование IMG (включая архив только с COL/CLS) с **отрицательными** тестами loose `custom/collision/`, валидных ZIP, корневых `img/` и `common/`.
