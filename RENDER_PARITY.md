# Материалы и освещение OpenGL/GL3 в reVC

Ориентир по рендеру клиента: [BR_LIB_ANALYSIS.md](BR_LIB_ANALYSIS.md),
`brso/shaders_reconstructed/`. Это **GLSL-реализация для reVC**, а не обещание
пиксельного совпадения с клиентом или загрузки его `.btx` из ZIP.

## Что видно в сборке `amd64-librw_gl3_glfw-oal`

По умолчанию машины идут через **GL3 MatFX**, а не Neo. Поэтому изменения
в `vendor/librw/src/gl/shaders/` затрагивают действительно используемые
материалы мира, педов и автомобилей. Опциональный Neo vehicle/road gloss
использует `src/extras/shaders/` и включается через существующее меню при
наличии `neo/neo.txd`; переключение на Neo не требуется для MatFX-улучшений.
D3D9-шейдеры, звуковой OAL и правила чтения пользовательских ZIP не менялись.

| Эффект | Реализация GL3 |
|---|---|
| Освещение | К вершинным ambient/динамическим источникам добавляется мягкое **попиксельное** солнце: нормаль интерполируется, `N·L` вычисляется во фрагменте, блик гаснет на обратной стороне и смягчается при облачности. RGB берётся из `CTimeCycle::GetDirectional*()`; при заходе солнца дополнительный свет исчезает. |
| Самозатенение | Мягкий переход на обратной стороне вместо резкого `pow(1−v_diffuse,24)`; интенсивность зависит от `GetShadowStrength()` и высоты солнца. Это **не shadow map и не отбрасываемая геометрией тень**. Штатные проекционные тени игры рисуются отдельно как прежде. |
| MatFX-отражения | Направление отражения считается **на пиксель** и переводится в UV через реальную матрицу envmap (учитываются её frame и `envMapFlipU`); нет вырожденного `normalize(refl.xy)` при виде прямо на поверхность. Fresnel учитывает цвет/освещённость материала `v_envColor` и существующий коэффициент MatFX. Туман накладывается после затенения, чтобы не затемнять цвет тумана. При отсутствии нормалей применяется диффузный путь. |
| Neo-отражения | `u_eye` используется в едином формате `vec4` от librw: нет конфликта объявлений/регистрации с `header.vert`. Направление отражения и Fresnel считаются во фрагменте, а не по вершинам крупных полигонов. Gloss использует фактическую нормаль дороги и не рисует блик с обратной стороны. |
| Атмосфера | Цвета неба/солнца/облаков берутся из штатного или разрешённого пользовательского таймцикла. Двухступенчатый градиент приходит ровно к цвету тумана на горизонте; низкие облака остаются видны в пасмурную погоду. Fog для обычного мира, кожи, MatFX, Neo и UV2 считается по расстоянию **до пикселя**, погода влияет на кривую воздушной перспективы; дальность отсечения не меняется. |
| Остальное | UV-трансформ и гамма сохраняются. Lightmap UV2 и проекционные тени игры не отключались. |

`rw::setSunDirection()`, `rw::setSunMaterialParams()` и
`rw::setAtmosphereParams()` получают время суток/погоду в
`CRenderer::ConstructRenderList()` только для GL3; `rw::gl3::setViewMatrix()`
загружает их в uniform'ы. `setLocalInvGamma()` по умолчанию равен `1.0`.
Настройка в `reVC.ini`:

```ini
[Rendering]
GL3Atmosphere=1
```

`1` — новое поведение (по умолчанию, даже при отсутствии файла INI), `0` —
прежние нативные цвета неба/тумана и линейный шейдерный fog. Пользовательский
`timecyc.json` при `0` по-прежнему влияет на освещение/силу штатных теней.
Переходы по погоде и часам используют уже существующую интерполяцию VC.
Это воздушная перспектива и оттенки существующих облаков, **не** объёмные
облака, shadow maps, HDR, постобработка или новые текстуры из ZIP. Без
пользовательских ассетов и визуального запуска нельзя обещать точное
совпадение с референсными скриншотами.

Исходные GLSL-файлы и встроенные `*.inc` следует обновлять вместе:
`make -C vendor/librw/src/gl/shaders` и `sh makeinc_glsl.sh <имя>.vert/.frag`
из `src/extras/shaders/`.

## Проверка шейдеров

`python3 tests/GL3ShaderTests.py` сравнивает все GLSL-исходники с реально
встраиваемыми в игру `.inc`. Если в `PATH` есть `glslangValidator` или задан
`GLSLANG_VALIDATOR=/путь/к/glslang`, тест также **компилирует и линкует**
стандартные world/skin/MatFX, Neo vehicle/world/gloss/rim и варианты
full-light/no-alpha-test для GLSL 120/330 и GLES 100/310.
В `tests/CMakeLists.txt` проверка добавлена в CTest при наличии Python 3.
Компиляция шейдеров и C++ **не подтверждает визуальный результат или запуск
игры**: для этого нужна GL3-сборка с игровыми данными.

## Таймцикл из `data/timecyc.json`

Если разрешённый `data/timecyc.json` есть в `custom/common.zip` (или loose
`custom/data/timecyc.json` как резерв), `CCustomTimecycle::Apply()` заполняет
таблицы `CTimeCycle` после `CTimeCycle::Initialise()`. Все бэкенды читают
ambient/directional цвет и силу штатных теней; GL3 дополнительно берёт цвета
неба/солнца/облаков. FogStart импортируется **только если присутствует также
FarClip**: отношение между ними переносится на неизменённую native-дальность
VC, а некорректные значения оставляют прежнее начало тумана. `FarClip`, вода,
PostFX и другие архивы в графике не используются. При отсутствии JSON остаётся
штатный таймцикл VC; при выключении новой опции — прежнее поведение.
